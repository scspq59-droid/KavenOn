# Zasady współpracy — KavenOn

Dziękujemy za udział w rozwoju projektu KavenOn. Poniższe zasady pomagają utrzymać czytelną historię zmian i sprawną współpracę.

## 1. Repozytorium i gałęzie

- Główna gałąź projektu: `main`.
- Każde zadanie powinno być realizowane w osobnej gałęzi.
- Nazwy gałęzi zapisujemy małymi literami, używając łączników, np. `feature/task-search`, `fix/task-filter`.
- Członkowie zespołu (poza Project Managerem) pracują na własnych forkach repozytorium.

## 2. Commity

- Wykonuj częste, niewielkie commity.
- Tytuł commita powinien krótko opisywać zmianę.
- Zalecany format: `type: short description`.
- Przykłady: `feat: add task search`, `fix: correct task filtering`, `docs: update README`.

## 3. Pull Request

Każdy Pull Request powinien zawierać:
- Jasny tytuł.
- Krótki opis wykonanych prac.
- Odnośnik do odpowiedniej karty Trello.
- Informację o problemach lub ograniczeniach, jeśli występują.

Przed wysłaniem Pull Request sprawdź, czy aplikacja uruchamia się poprawnie i czy zmiana nie psuje istniejących funkcji.

## 4. Przegląd i scalanie

- Project Manager sprawdza zmiany przed scaleniem.
- W razie potrzeby autor wprowadza poprawki.
- Po akceptacji Pull Request może zostać scalony z gałęzią `main`.

## 5. Styl pracy

- Pisz czytelny i możliwie prosty kod.
- Nie dodawaj do repozytorium haseł, kluczy API ani prywatnych danych.
- Zgłaszaj problemy zespołowi i aktualizuj status zadania na Trello.
